# ストップワード・同義語の設定ファイル（Issue #2130）

疎検索（BM25）のテキスト処理に、運用者が渡すストップワード一覧と同義語辞書を opt-in で加える。
対象ビヘイビアは SEARCH-16、タスクは TASK-254（いずれもポインタ表記のみ。spec 本文は転記しない）。

## 1. 位置づけ

- 設定の手段は起動時の CLI フラグ `--stopwords-file <path>`・`--synonyms-file <path>` に限る。
  SQL／NoSQL／`SET`／`HYBRID` の引数／表のオプションからは変えられない（1 つのテナントが他の
  テナントの検索結果を変えられないため）
- フラグを付けない場合のトークン化と検索結果は変更前と完全に同じ（恒等）
- 英語のステミング本体（#2129 Phase B）は依存の承認待ちで本件の対象外。ステマーは本件の
  処理の**後段**に入る想定で、`match_span::normalize_for_match` が拡張点になる

## 2. ファイル形式（PostgreSQL の stopword／synonym ファイルの厳格な部分集合）

| 項目 | 規則 |
| ---- | ---- |
| 共通 | UTF-8、行単位（`\r\n` 可）。前後の空白を除き空行は飛ばす。ASCII 大文字は小文字にそろえる |
| 語 | ASCII 単語（`[A-Za-z0-9_]`）のみ。BOM・非 ASCII・`#` 始まりのコメント・`*`（前方一致）は拒否 |
| ストップワード | 1 行 1 語。複数語の行・重複は拒否 |
| 同義語 | 1 行に `語 置き換え先` の 2 語。1 語・3 語以上の行は拒否。置き換え元の重複は拒否。`a a` は受理 |
| 整合性 | 同義語の置き換え先がストップワードに含まれる場合は起動エラー |
| 空ファイル | 項目 0 件として受理（設定としては恒等と同じ） |

PostgreSQL に対し「PostgreSQL では受理されるが本サーバーでは拒否」の方向にだけ狭めてある
（コメント行・前方一致・複数語の同義語・thesaurus は対象外）。

## 3. 上限（自動運転下の判断。人間の確認が要る）

engine の定数（`sparse::analysis`）を唯一の基準にし、読み込み側（wire-server）も同じ定数を参照する。

| 定数 | 値 | 意味 |
| ---- | -- | ---- |
| `MAX_TEXT_ANALYSIS_FILE_BYTES` | 1,048,576 | ファイルごとのバイト数 |
| `MAX_TEXT_ANALYSIS_ENTRIES` | 65,536 | ファイルごとの項目数 |
| `MAX_TEXT_ANALYSIS_WORD_BYTES` | 128 | 1 語のバイト数 |

検証順はバイト数 → 行ごとの語数・語長・文字種・重複 → 項目数（上限 +1 で打ち切り）。
読み込みは `take(上限 + 1)` で上限付きにする（`metadata` で確かめてから読む方式は TOCTOU になり、
無限のストリームも読み続けてしまうため使わない）。値の妥当性は運用実績で見直す。

## 4. 処理の順序と位置

PostgreSQL の辞書チェーンに合わせ、既存の walker（`walk_tokens_positioned`）の emit に対する
フィルタとして実装する（walker 本体は変えない）。

1. 同義語を 1 対 1 で 1 回だけ引く（連鎖しない。置き換え後は最終形）
2. 同義語に当たらなかった語だけをストップワードと照合し、該当すれば出さない
3. 除いたトークンも位置を 1 つ消費する（walker が emit の有無によらず位置を進めるため。
   PostgreSQL と同じ位置の欠けになり、既存の CJK ストップワードと同じ意味）

同義語は 1 対 1 でトークン数が増えないため、DoS の上限（一意語数・コーパストークン数）は変わらない。
ASCII 単語のトークンだけが照合対象で、CJK の処理は構造的に変わらない（CJK の一覧と形態素解析は
EXT-8 の範囲で対象外）。

## 5. 索引・クエリの対称性と失効

- `SparseIndex` は構築時に `Arc<TextAnalysis>` を固定し、クエリ側のトークン化にも同じ設定を使う。
  索引とクエリで設定がずれる経路を作れない
- 既存の `SparseIndex::build`／`with_params`／`tokenize` は恒等のまま。新 API は
  `build_with_analysis`・`with_params_and_analysis`
- 疎索引は永続化されず、プロセス内のキャッシュ（`sql::sparse_cache`）にだけ載る。設定は起動時にだけ
  読むので、設定を変えて再起動すれば古い索引は残らない。多層防御として:
  - `TextAnalysis` は構築ごとに一意の `analysis_id`（恒等は 0）を持ち、キャッシュの `lookup` が
    一致を確かめ、違えば stale として破棄する（BM25 の `k1`／`b` とは逆に、設定は世代に含める）
  - `EngineCore::with_text_analysis` は設定を差し替えるとき疎索引キャッシュを作り直す
- 設定は `execute_statement_with_cache` の専用引数で渡す（`SparseCacheAccess` には載せない）。
  書き込みトランザクション由来の読み取りではキャッシュが `None` に落ちるが、設定はその経路でも効く

## 6. フレーズ一致

`PhrasePattern` は作成時の `analysis_id` を持つ。`SparseIndex::phrase_matches*` は索引と設定が
違うパターンに対して空を返す（fail-closed。誤った一致を返さない）。設定付きのパターンは
`compile_with`／`from_phrase_with` で作る。

## 7. 対象外

- 英語のステミング本体（#2129 Phase B）、CJK の一覧と形態素解析（EXT-8）、前方一致・複数語の
  同義語・thesaurus 辞書
- 動作中の再読み込み、表ごとの指定、EXPLAIN への表示
- `text_query`・`match_span`（`ts_headline`）・`rerank` の語の重なり判定への結線。これらは既定の
  テキスト処理のままで、**設定はハイライトなどには効かない**

## 8. セキュリティ

- エラー文はフラグ名・行番号・理由だけで、ファイルの語や内容を含めない
- 不正な指定・値欠落・重複指定は黙って既定に戻さず起動を拒否する（fail-closed）
- 新しい依存はない（行単位の自作パーサ）
