# ALTER TABLE RENAME TO（表名変更・行ストアとカタログ名の付け替え）

Issue #1623（親 #1622、TABLE-38 のポインタ）。仕様本文は転記せず、実装上の判断だけを記録する。後続の #1624・#1625 は本ファイルに追記する。

## 設計判断

- **コピーしない**: 依存の redb には `WriteTransaction::rename_table` がある。マスターツリーのエントリを付け替えるだけの O(1) 操作で、行テーブル `user_rows/{table}` は物理キー `(tenant_id, id)` をバイト単位で保ったまま新しい名前へ移る。
- **テナント境界**: RLS 相当の境界は行ストアの物理キーと `PolicyContext` で決まり、テーブル名をキーに持つ RLS 設定表は存在しない。行テーブルを丸ごと改名すればテナント境界もそのまま移る（結合テストで他テナントから見えないことを固定）。
- **原子性**: カタログのエントリ・行ストア・世代の更新を `Storage::alter_table_rename` の単一 write txn で行い、`commit_boundary` で commit する。commit 前の失敗は txn ごと破棄され、クラッシュ後に見えるのは旧名か新名の一方だけ（SIGKILL 結合テストで確認）。
- **判定順序**: 構文段（識別子。カタログを見ない）→ 権限ゲート → 表の存在（`42P01`／`42809`）→ 改名先の衝突（表・ビュー・索引と同じ名前空間。同名を含む。`42P07`）→ 依存オブジェクトの暫定拒否（`0A000`）→ 付け替え。権限のない主体に存在オラクルを与えない。依存の判定はカタログ情報だけで行い、テナントの行や台帳の有無で成否を変えない。
- **孤児の fail-closed**: 改名先の名前に行テーブルが既に在る場合は統合も削除もせず拒否する。行テーブルは遅延作成のため、改名元に行テーブルが無い（一度も書かれていない）場合も、改名先に孤児の行テーブルがあれば同様に拒否し、無ければ成功扱い。
- **派生データの掃除**: `user_uniq/{table}`・`key_index` は旧名・新名の両方を同一 txn で削除する。遅延再構築される派生データなので安全で、残留が同名の再作成後に「構築済み」と誤認される fail-open を防ぐ。
- **世代**: 旧名・新名の両方の `table_generation` を進める。旧名のキャッシュを失効させ、新名で過去にキャッシュされたエントリとの衝突を避ける。
- **差し込み点**: 依存の暫定拒否は `catalog::refuse_rename_table_with_dependents_in_txn` に分離した。#1624・#1625 は項目ごとにここから外していく。主キー制約名は `<table>_pkey` から遅延導出されるため、PK を持つ表の改名は #1624 で制約名を維持する対応が要る。
- **エラー型**: 依存による拒否は crate 内部の `AlterCheckError::Sql` で返し、公開の `CatalogError` を増やさない。

## 破壊的変更

`ValidatedAlterTable::RenameTable`・`ValidatedAlterTableRenameTable`・`AlterTableAction::RenameTable` を追加した。これらを網羅 `match` するコードは追随が必要。

## 既知の制約

- `operation_id` 台帳・分割実行ジョブ表は表名キーのため、改名と同じ write txn で旧名・新名分を削除する（旧名の再作成で旧記録に当たる誤った冪等判定を防ぐ安全側の掃除）。台帳の削除は `last_op` も対象のため、改名後は直前の操作情報も失われ、改名前の `operation_id` の再送は新しい名前でも判定されない。`last_op` の追随は #1625。

## Issue #1624 追記（制約・FK・索引宣言の追随）

- **ゲート**: `refuse_rename_table_with_dependents_in_txn` はビュー依存（`0A000`、#1625 で解除予定）だけを見る。PK・UNIQUE・CHECK・FK・索引宣言の拒否は外した。
- **制約名は変えない**（PostgreSQL と同じ）。UNIQUE・FK・CHECK は実名をカタログに保持し、encode は実名と新しい表名から導出した名前が食い違えば名前を明示する版を自動で選ぶため、書き換え不要。PK は無名のとき `<table>_pkey` を遅延導出するので、`TableSchema::rename_table_references` が改名前の実効名を明示名へ固定し、`with_primary_key_name` を通す（往復改名で導出名に戻れば `None` へ正規化され、カタログ値のバイト列も元に戻る）。
- **FK**: 自己参照 FK の `parent_table` は自表の書き換えで付け替える。他表から参照される FK は `referencing_foreign_keys_in_txn` で子を列挙し、`parent_table` を付け替えて再 encode し、子の `table_generation` を進める（`id` 参照の FK を含む。参照アクション・制約名は不変）。自表のカタログを書く前に、`CATALOG_TABLE` のハンドルを持たない状態で列挙する。
- **索引宣言**: `rename_index_def_table_in_txn` が所有テーブル名だけを書き換え、1 件でも書けば索引カタログ世代を進める（HNSW 判定キャッシュの失効）。索引名・種別・列・照合は不変。
- **CHECK**: 述語テキストは列参照のみで表名修飾を含まないため書き換えない。
- **原子性**: すべて既存の単一 write txn 内。失敗すれば子・索引宣言・各世代とも変わらない（単体テストで固定）。
- **既知の制約**: 制約名の名前空間は表単位のため、改名後に旧名で表を作り直しても導出名の重複で衝突しない（PostgreSQL は索引名がスキーマ単位で衝突する）。この差は許容する。
