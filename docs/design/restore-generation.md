## 実装で確定した参照構文（Issue #2449）

- 参照は `SHOW restore_generation`（列名 `restore_generation`・`bigint`・1 行。全テナントで同じ値）
- 変更は `SET [SESSION|LOCAL] restore_generation ...` と `RESET restore_generation` を構文段で
  `42501`（固定文言）に拒否する。StartupMessage の同名パラメータは他の未知パラメータと同様に読み捨てる
- 世代を読めない場合は `XX000`（固定文言）で拒否し、値を丸めない（fail-closed）
- 取得時点の commit 番号は返さない（RECOVER-13 のポインタ）。NoSQL（HTTP）表層からの参照は対象外

## 復元をまたぐ高水位（Issue #3105）

物理の復元は新しい世代を `max(保存値 + 1, 時計の下限)` で決める。同じ復元元から繰り返し復元すると保存値は毎回
同じなので、増え方は時計だけで決まり、時計が戻る・同じマイクロ秒に並ぶ場合に後の復元の世代が前の復元を超えない
ことがある。復元元に書き込まずに復元をまたいで持つ高水位（これまでに発行した世代の最大値）が要る（RECOVER-17 の
ポインタ）。

### 採用案: `restore --generation-state <path>`（opt-in の状態ファイル）

- 指定したときだけ、そのファイルの高水位 `h` を読み、新しい世代を `max(保存値 + 1, 時計の下限, h + 1)` にする。
  新しい値を状態ファイルへ fsync してから公開する。保持できなければ何も公開しない（fail-closed）
- 指定しなければ従来どおり（時計の下限だけ）。既存の CLI・crash-test の挙動は変わらない
- 運用上の約束: 同じ DB 系列の復元では毎回同じ状態ファイルを指定する。状態ファイルの削除・差し替え・巻き戻しで
  保証が失われるのは運用者の責務とする（検知手段は持たない）
- PITR・増分つきの復元も同じ公開手順を通るので同時に対象になる。論理の復元への適用は対象外

### 不採用案

| 案 | 理由 |
| ---- | ---- |
| 復元元（`--from`）の隣に自動で置く | 読み取り専用・WORM の媒体から復元できなくなる。復元元のディレクトリへ書くので趣旨にも反する |
| 復元先（`--db`）の親ディレクトリに自動で置く | 別ディレクトリへの復元どうしで共有されない。出力ディレクトリに想定外のファイルが増え、crash-test の残骸検査を壊す。共有ディレクトリでは他者の削除で黙って保証を失う |
| redb の DB を状態ファイルにする | redb は open しただけでヘッダを書き換えるため、誤って既存の DB を指定すると検査の前に書いてしまう |

### 形式（engine の純粋なコーデック。`storage::{decode_high_water, encode_next_slot}`）

- 固定長 64 バイト = 32 バイトのスロット × 2（A/B）。各スロットは `magic(8) | seq(u64 LE) | value(u64 LE) | checksum(8)`。
  checksum は先頭 24 バイトの SHA-256 の先頭 8 バイトで、書きかけ・破損の検出用（認証ではない）
- 読み取り: 長さ 0 と全 0 の 64 バイトは新規（高水位 0）。それ以外で長さが 64 でない・有効なスロットが無い・値が
  上限超過・両側の `seq` が同じ、は拒否する（巻き戻さない）。読み取りは何も書かないので、誤指定した別のファイルを壊さない
- 書き込み: 有効な側と逆のスロットへ `seq + 1` で書いて fsync する。書きかけで止まっても直前の値が残る

### 手順（fail-closed。順序が保証を担う）

1. 引数の段階（何も開く前）に、空・`..`・シンボリックリンク・ディレクトリ・`--from`／`--db`／`--incremental`／
   アーカイブ先と同じファイル（別名・ハードリンクを含む）を終了コード 2 で拒否する
2. 整合検査の後、世代を進める直前に開く。親ディレクトリがグループ・その他から書き込めるなら拒否する。無ければ
   0600 で新規作成する。開いた fd の (dev, ino)・所有者・`mode & 0o077 == 0` をパスと照合する
3. 排他ロック（`File::try_lock`）を取り、公開の後まで保持する。取れなければ `in use` で公開しない
4. 高水位を読み、一時コピーの世代を高水位より大きい値へ進め、状態ファイルへ書いて fsync する。公開（`hard_link`）は
   その後。状態ファイルを書いた後に公開が失敗すると高水位だけが進むが、欠番は許されるので単調性は崩れない

エラー文は固定の英語でパス・値を含めない。依存の追加はない。
