## 背景

データベースの「復元の世代番号」を永続化し、物理の復元・PITR・論理の復元の完了時に進め、
セッションから読み取り専用で参照できるようにする（親 #2446）。
本書は、その進め方（単調増加の規則）と参照の構文を確定し、後続 Issue が同じ契約を前提に実装できるようにする。
バックアップ・マニフェスト・変更ログ・ダンプの具体的な形式は #2150・#2154・#2159・#2164・#2165 が確定する。
本書は世代を運ぶ契約のみを定める。

## 用語

復元の世代番号は、データベース全体で 1 つの非負 `bigint` で、復元という事象だけを数える。
`table_generation` や HNSW・スカラー索引・SQL アリーナの世代キャッシュ
（表・索引の更新に伴うキャッシュ無効化用）とは無関係である。
保存先の redb テーブル名・キー名もそれらと紛れない名前にする（例: テーブル `database_meta`、
キー `restore_generation`。最終名は #2448 で確定してよいが `table_generation` に似た名前は避ける）。

## 決定 1: 世代番号の決め方（単調増加）

- 新規作成した DB の世代は 0。値の範囲は `0..=i64::MAX`
- 復元の完了時の新しい世代 `g_new` は、次の 3 つの最大値とする
  - `g_src + 1`: 復元元（物理バックアップ・PITR の基点のバックアップ・論理ダンプ）に記録された世代
  - `g_target + 1`: 復元先に既に世代が記録されている場合のみ（既存の空 DB へ論理の復元を流す場合など）
  - `t_floor`: 復元を実行するホストの現在時刻の Unix エポックからのマイクロ秒。
    同じ元から繰り返し復元しても、後の復元が前回より大きくなるための下限
- 演算は `checked_add` 等で行い、異常はすべて fail-closed（世代を書かずに復元を拒否）にする
  - `g_src` または `g_target` が `i64::MAX`（`+1` が溢れる）
  - 時刻がエポック以前、またはマイクロ秒が `i64` に収まらない
  - 復元元の世代の記録が不正（範囲外・型違い・重複）
- 復元元の世代の記録が欠けている場合（本機能より前に作ったバックアップ・ダンプ）は `g_src = 0` とみなす。
  新しい値は `t_floor` で十分大きくなるため安全側である
- 保証しない範囲（設計判断）: 復元ホストの時計が戻った場合の大小関係と、同じ元を別ホストで同時に
  並行して復元した場合の大小関係。前者は運用者の時計管理の責務とし、後者は別 DB の事象として扱う
- 値は復元時刻の近似（マイクロ秒）を示しうるが、復元という事象そのものの情報である。
  バックアップ取得時点・commit 番号からは導出せず、それらは引き続き照会できない（RECOVER-13 ポインタ）
- 再起動・`SIGKILL` からの回復では値を変えず、読み出すだけにする

## 決定 2: 永続化と順序の契約

- redb のメタ用テーブルに 1 キーで保持する。キーが無い DB（本機能より前に作られた DB）は 0 として読む。
  このためカタログ形式版（`CATALOG_FORMAT_VERSION_*`）の更新は不要と判断する
  （#2448 で変える必要が生じた場合は、その Issue で理由を記録する）
- 保存値が壊れている（長さ不正・負値）場合は、DB のオープンを失敗させる（fail-closed）
- 復元は「整合検査 → 世代の書き込み → 復元完了の commit（fsync を伴う即時の永続化）」を
  1 つの最終トランザクションで行い、その後にサーバーが listener を開く。
  サーバーは起動時に値を読み込んで保持し、稼働中は変わらない。
  よって復元の後に古い世代を返す時間帯は構造的に生じない
- 復元の途中でクラッシュした場合は復元未完了として扱い（起動可否は #2154 の整合検査の範囲）、
  再実行で新しい（より大きい）世代を得る
- 物理バックアップは DB ファイルの複製に世代が含まれる。マニフェストへの併記の要否は #2150・#2154 の形式に従う
- 論理ダンプは DB 全体で 1 つの値を、ヘッダ相当の位置に記録し、復元 CLI だけが読む。
  SQL として流しても副作用の無い形にする。数字のみ・長さ上限・範囲を検証してから使い、
  SQL 文字列へ連結しない。具体的な符号化は #2451・#2159 に委ねる
- PITR は基点のバックアップの世代を `g_src` とし、変更ログの再生では世代を変えない
  （世代の書き込みを変更ログに載せない、または再生時に無視する）。再生の完了時に 1 回だけ進める。
  変更ログの形式は #2164・#2165 に委ねる
- 世代はテナント別のダンプにも同じ値で含めてよい（テナント情報を含まない）。テナント別の値は持たない

## 決定 3: 参照の構文

引数なしの組み込み関数 `fandhe_restore_generation()` を採用する。戻り値は `bigint`
（wire では `int8`・OID 20）で、NULL にならない。

### 比較した案

| 案 | 採否 | 理由 |
| ---- | ---- | ---- |
| 組み込み関数 `fandhe_restore_generation()` | 採用 | `SELECT` の式・比較・拡張クエリで使え、代入の構文を持たないため読み取り専用が構造的に成り立つ |
| 設定名 `SHOW fandhe.restore_generation` | 不採用 | `current_setting()` が未実装で `SHOW` 専用（text）になり、式として扱えない。`SET` の経路と同居し変更拒否の例外が増える |
| `pg_` 接頭辞の関数名 | 不採用 | PostgreSQL 本体の関数と誤認させる |
| 接頭辞なしの関数名 | 不採用 | 利用者の UDF と衝突しやすい |
| ParameterStatus での起動時通知 | 不採用 | 接続時の 1 回のみで、`SELECT` から参照できず、wire 層の変更が大きい |

### 変更の拒否

すべて既存の分類で表現し、新しい `wire_code` は足さない。

- `CREATE FUNCTION`／`CREATE OR REPLACE FUNCTION`／WASM UDF で同名を登録: `42723`
  （`is_reserved_function_name` に追加）。**互換性変更**である。
  既存の同名 UDF が呼べなくなるため、実装時に implementation-status へ明記する
- `SET`／`RESET`／`SHOW` で同名・類似の設定名を指定: 既存の unsupported SET variable 経路（`42601`）。
  #2449 のテストで固定する
- 引数付きの呼び出し: `builtin_call_arity` の引数個数検査で `42883`
- `55P02`（cant_change_runtime_param）で表す案は採らない。エラー分類表に無く、
  採用するなら spec 側の判断事項になる

### 決定性

復元をまたいで値が変わるため、IMMUTABLE として扱わない。索引の式・部分索引の述語・生成列・`CHECK` など
IMMUTABLE を要する文脈では `42P17` とする（`index_expr.rs` の非決定関数リストへ追加）。

### テナント境界

引数を取らず、テナント入力に依存しない。どのテナントのセッションでも同じ値を返し、
エラー文言にも値や他テナントの情報を載せない。
NoSQL（HTTP）表層からは参照を提供しない（HTTP は SQL を受けないため。HTTP 射影への影響は無い）。

## 受け入れ項目と検証担当

| 親 #2446 の目標 | 検証する Issue |
| ---- | ---- |
| 永続化・新規 DB で 0・再起動で不変・物理の復元で前回より大きく進む | #2448 |
| 読み取り専用の参照構文・変更の拒否・全テナント同値・古い世代を返さない | #2449（#2448 と結合） |
| PITR の完了時に 1 回だけ進む | #2450 |
| 論理の復元の完了時に進む | #2451 |
| 取得時点の commit 番号が照会できない（RECOVER-13） | #2448・#2449 |

## セキュリティ上の整理

- 参照関数は引数なし・テナント入力非依存で、他テナントの情報を含まない。管理者バイパスを作らない
- 世代はセッション変数・SQL 文・テナント資格情報から変更できない
- すべての異常（溢れ・時計異常・不正値・壊れた保存値）で fail-closed とする
