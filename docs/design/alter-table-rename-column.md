# ALTER TABLE RENAME COLUMN（列名変更・カタログのみ）

Issue #1619・#1620（親 #1618、TABLE-38 のポインタ）。仕様本文は転記せず、実装上の判断だけを記録する。

## 範囲

| 項目 | 本 Issue | 担当 |
| ---- | -------- | ---- |
| 構文 `RENAME [COLUMN] <old> TO <new>` と `sql::ddl` への接続 | 実装 | #1619 |
| カタログの列名の書き換え（行のバイト列は不変） | 実装 | #1619 |
| 制約・索引が参照する列の追随 | 実装 | #1620 |
| ビュー定義の参照の追随 | 単純形は追随、評価後射影形は拒否（`0A000`） | #1621 |
| 表の改名 `RENAME TO`・`IF EXISTS` | 構文エラー（`42601`） | 別 Issue |

## 設計判断

- **行は書き換えない**: 行ペイロードは物理スロットの位置で列を持ち、列名を含まない。改名は `ColumnDef.name` の更新と世代 bump だけの O(1) 操作で、カタログ形式のバージョンは変えない。DROP 済み列（墓標）の名前は名前空間の外なので、同名への改名は許可する。
- **制約・索引の参照を追随（#1620）**: 同一 write txn で PK・UNIQUE・FK（子側の列・自己参照の親列・他テーブルから見た親列）・索引宣言（scalar・hnsw）の列名を新しい名前へ書き換え、書き換えた各テーブルの世代と索引カタログ世代を bump する。制約名は変えない（UNIQUE・CHECK・FK の実名は永続化済みのため、再オープン後も同じ名前で復元される）。
- **CHECK は AST 経由**: 述語テキストの文字列置換は使わない。再パース → AST の識別子置換（完全一致・文字列リテラルや関数名は対象外）→ 既存の `build_check_constraint`（束縛・参照列の再計算・正規化レンダリング・長さ上限・往復一致）→ 参照列集合の同値検証、の順で行う。どこかで失敗したら `0A000` で全体を破棄する（txn を commit しない）。長い名前への改名で述語テキストが上限を超える場合などがこれに当たる。
- **派生索引の失効**: FK 検査用の永続キー索引（名前に列名を含む）は同一 txn で失効させ、次の検査で遅延再構築する。PK／UNIQUE 列なら永続一意索引も削除する。旧名の stale な索引が、後で同名に戻した列に対して「構築済み」と誤認される fail-open を防ぐ（ALTER COLUMN TYPE と同じ方針）。
- **ビューは追随（#1621）、追随できない形は `0A000`**: 単純形ビューの保存本文を書き換え、評価後射影形などは拒否する（下記「Issue #1621 追記」）。古い名前の参照を残したまま黙って壊れる経路を作らない（fail-closed）。
- **差し込み点**: ビュー定義の追随は `catalog::rewrite_views_for_renamed_column_in_txn` に分離した（#1621）。
- **判定順序**: 構文段（予約名・識別子。カタログを見ない）→ 権限ゲート → 表の存在（`42P01`／`42809`）→ 改名元の不在（`42703`）→ 改名先の衝突（`42701`。同名を含む）→ ビュー定義の追随失敗・CHECK の書き換え失敗（`0A000`）。権限のない主体に存在オラクルを与えない。
- **予約名**: 改名元・改名先が内部列（`id`／`tenant_id`／`visibility`）なら `42703`（TABLE-38）。キーワード衝突名（`check`／`constraint`）は `42601`（DROP COLUMN・ALTER COLUMN TYPE と同じ）。いずれも構文段で判定し、カタログを見ない。
- **エラー型**: 依存による拒否は crate 内部の `AlterCheckError::Sql` で返し、公開の `CatalogError` を増やさない。

## 既知の制約

- 改名の後に、同じ `operation_id` を新しい列名で再送すると内容ハッシュが列名を含むため `22023` になる（fail-closed 側）。
- NoSQL（HTTP）表層の `alter_table` に `rename_column` op は未追加。

## Issue #1621 追記（ビュー定義の追随）

TABLE-38 のポインタ。ビューの追随は `catalog::rewrite_views_for_renamed_column_in_txn` に分離した（#1620 でビュー検査の `refuse_rename_column_with_views_in_txn` は廃止し、本関数が置き換えた）。スキーマ書き込みの前に、同一 write txn で呼ぶ。

- **単純形ビュー**（`SELECT <* | 列リスト> FROM <rel> [WHERE 単純述語 ...]`）: 保存本文を再パースして AST の列参照（投影・述語）を書き換え、既存レンダラー（`render_stored_simple_view_body`。`CREATE VIEW` と共有）で再描画する。文字列置換はしない。親（表、または連鎖の単純形ビュー）が改名元を公開している場合に限って書き換える。改名元を公開しない枝や、無関係な表で同名の列を使うビューは本文がバイト単位で不変。
- **評価後射影形ビュー**（集計・JOIN・CTE・`ORDER BY`・`LIMIT`・集合演算・式）: 保存しているのはトークン列の描画で、`Ident` は別名・関数名・JOIN 相手側の同名列と区別できない。このため、表を読む、または改名元を公開する単純形ビューを読む場合は `0A000` で拒否する。どちらにも当たらないものは影響を受けないので許可する。
- **fail-closed**: 再検証できない本文・公開列の導出失敗は `0A000`。追随後の本文が上限を超えるときは `54000`。計画をすべて確定してから書き込み、書き込みはスキーマと同一 txn（拒否時はビューもスキーマも不変）。再描画した本文は、元の往復検証と改名後の親の公開列に対する列スコープ検査を通してから保存する。
- **PostgreSQL との差**: PostgreSQL ではビューの出力列名は変わらないが、本実装の単純形ビューは別名を持てず `SELECT *` も動的に展開されるため、ビューの公開列名も新しい名前に変わる。出力列名を維持する挙動は列の別名・列名リストの対応（TABLE-41 系）が前提で、対象外。

### 既知の制約（#1621）

- 評価後射影形ビューを持つ表の、そのビューが読む列の改名は拒否される（追随は未対応）。
