# jsonpath 評価のステップ数・再帰深さ上限の起動時設定（CLI）

## ステータス・対象

- ステータス: 採用（Issue #2184・TABLE-25 のポインタのみ。spec 本文は転記しない）
- 対象フラグ: `--max-jsonpath-steps`・`--max-jsonpath-depth`
- 先行: [group-by-limits-cli.md](group-by-limits-cli.md)（Issue #1550）と同型

## 背景

jsonpath 評価器（`engine::json::jsonpath::jsonpath_query` ほか。意味論は [json-expr-type-mapping.md](json-expr-type-mapping.md) の「Issue #2184 での変更」）は、`$.**.**.**` や `$[*] ? (@ == $[*])` のような病的なパスで評価コストが入力の積や冪に膨らむ。解析器が拒否する静的な上限（入力長・入れ子・リテラル長・式の高さ）では防げないため、**評価時**にステップ数と再帰深さを数えて制限する。運用者が `--max-group-by-columns` 等と同じ方式で起動時に下げられるようにする。

## 決定

| # | 内容 |
| - | ---- |
| D1 | ハード上限がそのまま既定値。ステップ数 `4,000,000`（`MAX_JSONB_CONTAINMENT_STEPS` と同じ桁）・再帰深さ `1,024`（解析器の式の高さ上限と同じ）。設定できるのは**下げる方向だけ**（範囲は `1..=4000000`・`1..=1024`）。引き上げは評価器の安全弁を外すことになるため対象外 |
| D2 | 超過は SQLSTATE `54000`（fail-closed）。`silent`（`jsonb_path_*` の同名引数相当）でも、述語内でも抑止されず、必ず呼び出し元へ返る |
| D3 | 値の運搬は `group_by_limits` と同型。`engine::jsonpath_limits::JsonPathLimits`（`Copy`・フィールド非公開・ハード上限で飽和）を `EngineCore::with_jsonpath_limits` で起動時に 1 回注入する。プロセス大域の状態は使わない（Issue #2185 の運搬方式は D4）。範囲検証は engine の `validate_*` に一本化し、wire-server は CLI 文字列を厳密パース（先頭 `+`・空白・全角数字・空文字を弾く）して渡すだけ |
| D4 | `jsonb_path_*`（Issue #2185）は、文の束縛区間に限った thread-local の RAII スコープ（`sql::jsonpath_fn::JsonPathLimitsScope`。`time_fn::ClockScope` と同型）で `EngineCore::jsonpath_limits` を束縛へ運び、束縛時に束縛結果へ焼き込んで評価の `JsonPathEvalOptions::with_limits` へ渡す。スコープが張られない経路はハード上限にフォールバックする（ハード上限が最大値なので無制限にはならない）。`@?`／`@@`・`JSON_EXISTS` は #2186・#2187 が同じ方式で配線する |
| D5 | フラグ名は `--max-jsonpath-steps <1-4000000>`・`--max-jsonpath-depth <1-1024>`。範囲外・非数値・値欠落は起動エラー。2 回目以降の指定は fail-closed（last-wins にしない）。解決は bind・ユーザーストア読込より前 |

## 「ステップ」と「深さ」の定義

| 量 | 数え方 |
| -- | ------ |
| ステップ | AST ノードの評価 1 回、アクセサが訪問／生成した項目 1 件、比較の組 1 組、子項目の列挙（子の数）、評価結果の複製（ノード数）を 1 ずつ。`.**` や `[*]` の走査、`$[*] ? (@ == $[*])` の組合せ爆発は、必ずこのいずれかで課金されて上限に当たる |
| 深さ | 評価器の再帰（式の入れ子・アクセサ連鎖・フィルタ内の再評価）の入れ子数。解析器が拒否する静的な式の高さ（`MAX_JSONPATH_NODE_HEIGHT`）とは別の、実行時の値。`.**` の JSON 走査は再帰でなく明示スタックで行い、深さに含めない（JSON 側は `MAX_JSON_DEPTH` で別途有界）。左結合の算術連鎖（`1 + 1 + ...`）は再帰せず反復で畳む |

評価器が新たに作る値（`.keyvalue()` の組）は `MAX_JSON_DEPTH` 超過を、評価中の項目列は 1,048,576 件超過を `54000` で拒否する（メモリを有界にする安全弁。TABLE-25 の結果への深さ・要素数上限の適用そのものは、結果を直列化する呼び出し側が担う）。

## スタック

評価器の再帰 1 段あたりのスタック消費が小さくなるよう、再帰の経路に載る関数は振り分けだけを行い、局所変数の多い処理は別関数へ出している。最悪形（深さ上限ちょうどの `$` + 1,000 個のアクセサ連鎖）は、最適化なしのビルドでも 2 MiB のスレッドで溢れないことを確かめている（`crates/engine/tests/jsonpath_eval.rs`）。

## 対象外

- ハード上限の引き上げ
- 解析器側の上限（入力長・入れ子・リテラル長・式の高さ）の CLI 化
- セッション単位の `SET` による変更
