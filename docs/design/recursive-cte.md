# WITH RECURSIVE（再帰 CTE）

親 Issue #1868 の実装ツリー全体の設計メモ。ビヘイビアのポインタは SQL-35（主）・SQL-29（改訂注記）・
SQL-63 (3)（再帰 CTE 内のデータ変更）・ERR-6（`42P19`）・RLS-10 (b)。spec 本文は転記しない。

## 段階 A（Issue #1869）: 構文の受理と再帰構造の検証

実装は `crates/engine/src/sql/recursive_cte.rs`。`validate_sql_tokens_impl` の `WITH` 分岐が先頭の
`RECURSIVE` を検出した時点で分岐し、非再帰経路（`cte::resolve_relation`）へは流さない。流すと自己参照が
同名の実テーブルへ黙って解決されるため（シャドーイングの防止。fail-closed）。

### 受理文法

`WITH RECURSIVE <name> [(<列名>, ...)] AS [[NOT] MATERIALIZED] (<アンカー項> UNION [ALL] <再帰項>)[, ...] <主クエリ>`

- アンカー項は自己参照を持たない。再帰項は自己参照を FROM／JOIN の位置にちょうど 1 回持つ
- 再帰項は括弧で囲める（囲んだ内側の `LIMIT` などは項自身の句として扱う）
- 本文の閉じ括弧の直後の `SEARCH ... SET` 句は評価される（段階 C。#2213）。`CYCLE ... SET ... USING` 句も評価される（段階 D。#2214）

### コードの 3 区分と判定順序

判定順序は ①構文（`42601`）→ ②再帰構造（`42P19`）→ ③機能ゲート（`0A000`）。②は
`StructuralOnlyLookup`（カタログを照会しない）で行うため、同名の実テーブル・参照先テーブルの有無・
テナントで wire_code と文言は変わらない（存在オラクルを作らない）。

| 区分 | wire_code | 例 |
| ---- | --------- | -- |
| 構文不正 | `42601` | `AS`／括弧の欠落、本文内の `;`、CTE 名の重複、空の列名リスト、主クエリが SELECT で始まらない、再帰項のベクトル順位付け |
| 不正な再帰 | `42P19` | アンカー項に自己参照、再帰項に自己参照が 2 回以上（または 0 回）、部分クエリ・外部結合の NULL 側・`INTERSECT`／`EXCEPT` の中、集計・ウィンドウ関数・`LIMIT`／`OFFSET`／`ORDER BY`（括弧付き再帰項の内側）、`UNION` の無い自己参照 |
| 認識できるが未対応 | `0A000` | 再帰 CTE 本文のデータ変更、前方参照・相互再帰、入れ子の `WITH`、括弧の無い再帰項の末尾 `ORDER BY`／`LIMIT`／`OFFSET`／`FETCH`（段階 B 以降は評価できる形だけを実行し、`UNION`・複数定義などは引き続き `0A000`） |

定義数の上限超過は既存の CTE と同じ `54000`。

### 自己参照が 0 個の WITH RECURSIVE

PostgreSQL では通常の CTE として扱われるが、段階 A では安全側に倒して構造検証のあと `0A000` で止める。
RECURSIVE の下では後方の CTE 名も可視になり、非再帰経路の名前解決（同名の実テーブルへ解決）と意味が
食い違うおそれがあるため。通常 CTE としての実行は段階 B（#1870）で実装した（後方参照は段階 A が `0A000` にするため意味は一致する）。

### PostgreSQL との差分

- 括弧の無い再帰項の末尾 `LIMIT`／`ORDER BY` は PostgreSQL も未実装（`0A000`）で、本実装も `0A000`。
  括弧で囲んだ再帰項の内側は `42P19` とする（SQL-35 (2) に従う）

## 段階 B（Issue #1870）: 反復評価器

実装は `crates/engine/src/sql/recursive_eval.rs`。`WITH` 分岐の組み立ては `sql::allowlist` の
`recursive_cte_statement`。ビヘイビアのポインタは SQL-35 (1)(3)(4)・SQL-34・SQL-62・RLS-10 (b)・ERR-6。

### 方式（作業表方式）

アンカー項の結果を最初の作業表とし、各反復では「前回の反復で増えた行だけ」を作業表として再帰項を
再実行する。作業表が空になったら終了する。結果は「アンカー行 → 反復 1 → 反復 2 …」の生成順で、
`sort_unstable*` は使わない。基底表はストレージ上の表なので、作業表はメモリ上の行集合で持つ。
導出表も作業表を SQL へ書き戻す方式も使わない。

- **文の形**: `WITH RECURSIVE` の結果集合を新設の `Statement::RecursiveCte`（`ValidatedRecursiveCte`）で表し、
  主クエリの外側（WHERE・ORDER BY・射影・集計・LIMIT）は評価後射影形ビューと同じ `BufferedView`
  （`origin: MaterializedCte`）の外側処理に重ねる。Describe も同じ計画を通る。`BufferedOrigin` に再帰情報を
  載せず別 variant にしたのは、未対応の経路がアンカー項だけを実行して誤った結果を黙って返す（fail-open）
  のを、網羅 `match` とコンパイルエラーで防ぐため。`Statement` への variant 追加は破壊的変更。
- **アンカー項**: 実カタログで検証し、既存の読み取り経路（`FROM` なしの定数式だけ専用の実行本体）で実行する。
- **再帰項の検証**: `RecursiveTermLookup` が CTE 名だけを「実在する表（ビューではない）」として返し、
  他は実カタログへ委譲する。同名の実表・ビューは CTE 名に隠れる（シャドーイング）。受理する形は
  `Scan`（`SELECT <列|式> FROM <cte> [WHERE ..]`）と、CTE をちょうど 1 回含む `Join`。
- **再帰項の評価**: アンカー項の結果列（列名リスト適用後）から作業表の合成スキーマを作り
  （`sql::view_buffered::synth_schema`）、再帰項をそのスキーマに対して既存の束縛器で束縛する。
  `WHERE`・式の評価は評価済みセル用の既存部品を再利用し、式の結果セルへの変換は
  `sql::scan::computed_value_to_cell`（走査と共有）。JOIN の再帰項は `sql::join::prepare_join` で束縛し、
  基底表側は反復の前に 1 度だけ走査して、作業表側の行だけを毎反復で差し替えて結合以降を実行する。
- **列整合**: アンカー項の列を正とし、再帰項との列数・型は集合演算（`UNION ALL`）と同じ規則で検査する
  （`42804`）。列名リストが長すぎるときは既存の CTE と同じ `42601`。疑似列 `id` を結果列にした
  アンカー項の列は、作業表では BIGINT の実列として扱う。
- **自己参照 0 個の `WITH RECURSIVE`**: `RECURSIVE` を除いたトークン列を通常の `WITH` 分岐へ再入させ、
  通常 CTE として実行する。

### 上限（既定値。#1871 で起動時設定化済み）

| 項目 | 既定値 | 超過時 |
| ---- | ------ | ------ |
| 反復回数（再帰項の実行回数。0 行になる最後の実行を含む） | 1,000 | `54000` |
| 累積行数（アンカー行を含む。`--max-result-rows` が小さければそちらが先に効く） | 100,000 | `54000` |
| 累計バイト予算（走査・JOIN の確保には保持済みを差し引いた残予算を上限として渡す） | 既存の JOIN・走査と同じ共有予算。結果・基底表側の行・JOIN の作業表側の一時行を 1 つの予算へ確保前に計上する（作業表は結果の末尾区間を参照し、深い複製を作らない） | `54000` |

行数・バイト数は 1 行ずつ確保前に判定し、超過は結果を打ち切らず文全体を拒否する（部分結果を返さない）。
反復ごとに `interrupt::check()` へ協調する（`57014`）。

### 不変条件（RLS-10 (b)）

基底表の読み取りは参照セッション自身の `PolicyContext` と同一の `read_txn` で、既存の走査経路
（RLS 暗黙適用）を通る。`ValidatedRecursiveCte` はテナント情報を保持しない。作業表は前回反復の可視行から作った
値だけで構成されるため、停止時点・反復回数・`54000` の有無は可視行だけで決まる。CTE 名は決してストレージから
引かない（`recursive_cte_tables` が基底表の収集から除外する）。

### 受理しない形（`0A000` または各エラー）

- 複数定義（非再帰定義との混在、複数の再帰定義）、ビュー本文・cursor・COPY・CTAS・
  `INSERT ... SELECT`・サブクエリ内・NoSQL 表層の `WITH RECURSIVE`（セッション最上位の SELECT 入口だけが組み立てる）
- 再帰項: 部分クエリ・導出表、`ORDER BY`・`LIMIT`・`OFFSET`・ウィンドウ関数、集計、疑似列 `id`
  （作業表は行 id を持たない行識別方式の合成スキーマで束縛するため、式・述語・JOIN 条件を含む全参照が未知列として
  拒否される。`SELECT *` は実列だけへ展開される）、JOIN の射影の式項目（JOIN の `SELECT` リストが列参照のみという
  既存の制約）、非バイト列順の照合（ICU）の列を持つ表を参照する再帰（照合を作業表へ運べないため固定の `0A000`。TABLE-28）
- 作業表の列型: アンカー型を正とし、再帰項が異なる整数型（`SMALLINT`／`INTEGER`／`BIGINT` の拡大）を返す形は
  `42804`（PostgreSQL と同じ。例: `SELECT 1` のアンカーに `BIGINT` を返す再帰項は `CAST(1 AS BIGINT)` と書く）。
  疑似列 `id` のアンカー・再帰項の列は作業表では `id` 型（numeric(20,0)。`u64` 全域を損失なく運ぶ。単一の写像 `work_column`）で、
  公開結果列の公告（numeric）と値（`u64`）は元のまま。`id` 型の列への算術・`id` 型かどうかが両項で食い違う列は拒否する。
  JOIN の再帰項でも `id` 型の列は CTE の行 `id`（`CteIdColumns`。#2729 と同じ写像）として結合へ渡し、セルは `u64` のまま運ぶ。述語・式へ渡せない型
  （`TIME`・`TIMESTAMPTZ`・`INTERVAL`・`JSONB` 等）は計画時（Describe も同じ）に固定 `0A000`
- 主クエリ: CTE 以外の表の読み取り・JOIN、式射影、序数 `ORDER BY`（評価後射影形ビューの外側と同じ制約）

静的に決まるエラー（アンカーの束縛・再帰項の束縛・列数・型・照合・未対応型）は、Execute でもアンカーを実行する前に Describe と同じ経路で検査する（データ依存の実行エラーに覆われない）。

## Issue #1871 追記（上限の起動時設定化）

ポインタ: SQL-35 (3)・SQL-46・SQL-34・RLS-10 (b)・ERR-6。

| 項目 | 内容 |
| ---- | ---- |
| フラグ | `--max-recursive-cte-iterations <1-1000>`・`--max-recursive-cte-rows <1-100000>` |
| 既定値 | 反復 1,000 回・累積 100,000 行（#1870 の暫定値と同じ。フラグ未指定なら挙動不変） |
| ハード上限 | 既定値と同じ。設定できるのは**下げる方向だけ** |
| 最小値 | どちらも 1 |
| 実装 | engine の `recursive_cte_limits`（範囲検証の単一情報源）→ wire-server の `recursive_cte_limits_opt`（厳密パース）→ `EngineCore::with_recursive_cte_limits` へ起動時に 1 回だけ注入 |
| 異常入力 | 範囲外・非数値・値欠落・重複指定は起動エラー（既定へ黙って読み替えない） |

- 反復回数の数え方は #1870 と同じ（再帰項の実行回数。0 行になる最後の実行も含む）。上限ちょうどは受理し、1 超過で `54000`。
- 累積行数の実効上限は、設定値と `--max-result-rows`（SQL-34）の小さい方（`RecursiveLimits::from_settings`）。
  2 つの設定値は互いに連動しない。
- Describe は上限を使わないため成功し、Execute で `54000` になる。
- 上限はセッション・SQL・NoSQL・資格情報から変えられず、全テナントで同じ値になる。停止時点と `54000` の有無は
  可視行だけで決まり、RLS-10 (b) の不変条件は変わらない。
- ハード上限を既定値と同じにした理由: fail-closed と DoS 対策（既存の `join_limits`・`correlated_limits` と同じ作り）。
  累積行数は `--max-result-rows`（最大 100,000）との合成で上げても効かず、反復回数は JOIN の再帰項が反復のたびに
  結合をやり直すため、上げる方向は見送った。
- 累計バイト予算は従来どおり固定でフラグを設けない。

## 段階 C（Issue #2213）: `SEARCH DEPTH／BREADTH FIRST` 句

文法: `SEARCH {DEPTH | BREADTH} FIRST BY 列[, ...] SET 順序列`（定義の閉じ括弧の直後）。
`SEARCH` は構文段（`sql::allowlist`）で `SearchClause` として字句解析済みトークンから構造化し（SQL 文字列へ
再連結しない）、評価は `sql::recursive_eval`（`SearchPlan`）が行う。

### 意味（PostgreSQL 17 の書き換えと同じ）

| 方式 | 順序列 | 型（RowDescription） |
| ---- | ------ | -------------------- |
| `DEPTH FIRST` | 根から当該行までの BY 列の行値の配列（アンカー行は `ARRAY[ROW(by...)]`、再帰行は親の経路の末尾へ自分の `ROW(by...)` を足す） | `record[]`（OID 2287） |
| `BREADTH FIRST` | `ROW(深さ, by...)`（アンカー行は深さ 0、再帰行は親の深さ + 1） | `record`（OID 2249） |

- 「親」は再帰行を生んだ作業表の行。親の対応付けは、単一関係の再帰項では `ScanTerm::eval_over_rows` が返す入力行の位置、
  JOIN の再帰項では `PreparedJoin::run_with_sides` の出力行ごとの作業表側の行の添字（`run_with_sides_provenance`）を作業表の位置へ引いて得る
- 順序列は公開列（列名リスト適用後）の末尾に付き、主クエリの `SELECT *` に現れる。作業表のスキーマ・再帰項の束縛・列整合には含めない
  （再帰項からは未知列）。主クエリでは射影と、列キーだけの `ORDER BY 順序列 [DESC]`（他の列キーとの併用可）を受理する
- 比較は PostgreSQL の btree 比較に合わせる: レコードは先頭フィールドから順に比較し NULL は非 NULL より後（NULL 同士は等しい）、
  配列は要素ごとに比較して共通部分が等しければ短い方が先。`DESC` は全体を反転する。安定ソート
- テキスト表現は `record_out`／`array_out` の引用規則（`engine::sql::record_text`）。例: 幅優先 `(0,1)`、深さ優先 `{(1),(2)}`、
  BY 2 列の深さ優先 `{"(1,a)","(2,b)"}`、NULL フィールドは空 `(0,)`。HTTP の SQL 応答（NoSQL 表層）は型名 `record`／`_record`・値を入れ子の JSON 配列で返す
  （`[f1, ...]`／`[[f1, ...], ...]`）
- 値の表現: `Cell::Record(Vec<Cell>)`／`Cell::RecordArray(Vec<Vec<Cell>>)` と `ColumnMeta::Record { name, fields, array }`
  （`fields` の `None` は行 id 型の列）。カタログ型（`ColumnType`）には足さず、表へ保存される経路を作らない。保存・JOIN キー・
  集合演算・集計・カーソル・COPY・CTAS などへ到達した場合は `0A000`／`Internal` で拒否する（text へ黙って変換しない）。
  バイナリ結果形式（`record_send`）は未対応で、要求すると `0A000`

### エラー（SQLSTATE は PostgreSQL 17 の `src/backend/parser/parse_cte.c` に合わせる）

| 条件 | wire_code |
| ---- | --------- |
| 句の構文不正 | `42601` |
| BY 列が CTE の列名に無い・SET 名が CTE の列名と衝突・自己参照を持たない定義への `SEARCH` | `42601` |
| BY 列の重複 | `42701` |
| アンカー項（UNION の左辺）が集合演算 | `0A000` |
| `SEARCH` と `CYCLE` の併用 | 評価できる（#2214。列順は順序列 → 印 → 経路） |
| BY 列の数が列数の上限を超える | `54000` |

判定順は構文（`42601`）→ 再帰構造（`42P19`）→「自己参照が無い」の `42601` → 機能ゲート（`0A000`）。名前の解決は列が確定する計画段
（Describe と Execute が共有）で行う。

### PostgreSQL との差分（fail-closed 側に倒したもの）

- 並べ替えできない型（`VECTOR`・`ARRAY`・`JSON`・`CHAR(n)`・型なし）の BY 列は、PostgreSQL が並べ替え時まで遅延するところを計画時に固定 `0A000` で拒否する
- 順序列を外側の `WHERE`・式・ウィンドウ・集計・`GROUP BY`・式の `ORDER BY` キー・フィールド参照で使う形は未対応（合成スキーマ上で到達不能名のため未知列として拒否）
- 順序列のバイナリ結果形式は未対応

### 上限と RLS-10 (b)

深さ優先の経路は深さに比例して増える（O(深さ) の複製）ため、順序列は **確保・複製の前に** 共有バイト予算（`RowBudget`。結果・作業表と同じ予算）へ計上し、
超過は文全体を `54000`（部分結果なし）。順序列の値は参照セッションの可視行から作った BY 列のセルだけで構成され、他テナントの行は経路・順序・
`54000` の有無に影響しない（結合テスト `sql35_recursive_cte_search.rs` の RLS ケース）。

| 項目 | 担当 |
| ---- | ---- |
| `CYCLE` 句（`SEARCH` との併用を含む） | #2214（実装済み。「Issue #2214 追記」節） |
| `UNION`（重複除去）と `SEARCH` の併用 | 未割当（#1872 では固定 `0A000` で拒否。要 Issue） |

## Issue #1872 追記（`UNION` の重複除去と循環の停止）

SQL-35 (1)・SQL-25 (c)・SQL-29 (c)・RLS-10 (b)・ERR-6 のポインタ。

### 意味（PostgreSQL 17 の RecursiveUnion に合わせる）

| 項目 | 挙動 |
| ---- | ---- |
| アンカー項 | アンカーの結果の中でも重複を除く（入力順で最初の行を残す） |
| 各反復 | 再帰項の出力から、結果に残った全行および同じ反復で先に出た行と同値の行を捨てる |
| 捨てた行 | 結果にも次の作業表にも入れない。作業表が空になるので循環でも止まる |
| 出力順 | 生成順（`sort_unstable*` は使わない） |
| `UNION DISTINCT` | `UNION` と同じ |

### 実装

- 検証済みの文 `ValidatedRecursiveCte.union_all` が演算子を運ぶ。型検査（`compose_columns`）は `UNION` のとき集合演算 `UNION` と同じ検査を通す。
- 同値判定は集合演算 `UNION` と同じ行キー（`set_op::row_key`／`row_key_len`、`pub(crate)` 化）を再利用する（`DedupSet`）。第 2 の比較器は作らない。NULL 同士は等しく、`-0.0`＝`+0.0`、numeric は scale を無視する。
- 予算: キーは確保の前に共有バイト予算へ `Charge::Fixed`（行数に数えない）で計上する。Scan の再帰項は候補行を `Charge::Scratch` で作り、未出の行だけを `RowBudget::promote` で結果へ付け替える（行数上限はそのときに判定。重複は `max_rows` に数えない）。JOIN の再帰項は出力行を重複除去してから `admit` する。`HashSet` の確保失敗は `54000`。
- 型ゲート: 等値を持たない `JSON` 列（および `JSON` の配列）は `UNION` のとき計画段で固定 `0A000`（PostgreSQL でも recursive UNION を実装できない型）。`VECTOR` は再帰項の束縛段で参照できず拒否される。非再帰の集合演算 `UNION` が `JSON` を文字列で比べる既存挙動は変えない。
- `SEARCH` 句と `UNION` の併用は、順序列を含めた重複判定（PostgreSQL は順序列を両項へ書き足してから UNION する）が必要なため、順序列なしで黙って比較しないよう固定 `0A000` で拒否する。担当は未割当（要 Issue）。

### RLS-10 (b)

基底表の読み取りは従来どおり参照セッションの `PolicyContext` と同じ `read_txn` を通る。重複除去の集合は可視行から作った値だけで構成されるため、止まる時点・行数・`54000` の有無から他テナントの行の存在を観測できない。

## Issue #1873 追記（RLS 境界テスト）

ポインタ: RLS-10 (b)・SQL-35（補助: SQL-46・SQL-34・TABLE-12・ERR-6）。engine 本体は変更しないテスト追加のみ。

テストは `crates/engine/tests/rls10_recursive_cte_paths.rs`。`sql35_recursive_cte_*.rs` の機能単位の RLS ケースとは別に、横断マトリクスとして置く。

### 「各反復」の読み取り点

| 読み取り点 | 内容 | 確かめ方 |
| ---------- | ---- | -------- |
| アンカー項 | 通常の読み取り経路（参照者の `PolicyContext`・同一 `read_txn`） | 他テナントの Private な根・子が結果に現れない |
| JOIN 形の基底表側 | 反復の前に 1 度だけ走査し全反復で使い回す | 各深さに他テナントの Private な子・橋渡しを置き、深さごとの集合が変わらない |
| 作業表 | 前回反復の可視行から作った値だけ | 他テナントの行で作業表が延びない・止まらない |

### 検証軸

- 閲覧者 3 テナント × 可視性 2 モード（Public のみ／Private 込み）× SQL 形（Scan 形・JOIN 形の `UNION ALL`／`UNION`・`SEARCH DEPTH／BREADTH FIRST`・外側の集計と絞り込み・辺の循環）
- 独立オラクル: 真実値から純 Rust で期待結果（深さごとの集合・経路・重複除去後の集合）を計算する。production の可視性判定は呼ばない
- baseline／flooded: 参照者から見えない行（他テナントの Private）だけを足した状態で、応答が完全一致する。Public しか持たない対照テナントとも一致する
- TABLE-12 の衝突（同じ `node_id`・`parent_id` を他テナントが持つ）・橋渡し・循環を閉じる辺を fixture に含める

### エラー応答とカナリア

- 静的エラー（`42804`・`42P19`・`0A000`）は `wire_code`・`client_message` とも変わらず、他テナントの情報を含まない
- データ依存の `54000` は陽性対照つきのカナリアで固定する。他テナントの行だけが超過の原因になる設定で、閲覧者の応答は成功のまま変わらず、同じ設定で他テナント自身の応答だけが `54000` になる（反復回数・累積行数・JOIN 入力行数・`--max-result-rows`・`UNION ALL` の循環）
- 累計バイト予算のカナリアは fixture で決定的に超えさせにくいため対象外

### 空振り防止

軸ごとの件数と非空結果の assert、キャッシュの温め順序（A→B→A）の一致、捏造した違反を検査器が検出する負の対照を置く。

## Issue #2214 追記（`CYCLE` 句）

SQL-35・RLS-10 (b)・ERR-6 のポインタ。実装は `sql::allowlist`（`CycleClause`／`CycleConst`）・`sql::recursive_cte`（構造検証）・
`sql::recursive_eval`（`CyclePlan`）。

### 文法

`CYCLE 列[, ...] SET 印列 [TO 値 DEFAULT 既定値] USING 経路列`（`SEARCH` の後ろに続けられる）。`USING` は必須（無ければ `42601`）。
`TO`／`DEFAULT` の定数は PostgreSQL の `AexprConst` に合わせ、符号なしの数値・文字列・引用符なしの `TRUE`／`FALSE`／`NULL`・型名付き文字列だけ
（`TO -1` や任意の識別子は `42601`）。句は字句解析済みのトークンから構造体へ組み立て、SQL 文字列へ再連結しない。

### 意味（PostgreSQL 17 の書き換え `rewriteSearchAndCycle` に合わせる）

| 項目 | 挙動 |
| ---- | ---- |
| アンカー行 | 印 = `DEFAULT` 値、経路 = `ARRAY[ROW(循環列...)]` |
| 再帰行 | 新しい行の `ROW(循環列...)` が親の経路（親自身を含む）のどれかと `=` で等しければ印 = `TO` 値、そうでなければ `DEFAULT` 値。経路は親の経路の末尾へ自分の行値を足す（深さ優先 `SEARCH` と同じ生成器を共有） |
| 次の作業表 | 印が `TO` 値と等しくない行だけ。循環した行は結果に残るが、そこから再帰しない。`TO` と `DEFAULT` が同じ値なら、どの行も再帰しない |
| 等値 | SQL の `=`。フィールドに NULL があれば一致しない（`ROW(1, NULL)` どうしは循環にならない。btree の「NULL 同士は等しい」比較は使わない） |
| 列順 | ユーザー列 → `SEARCH` の順序列（あれば）→ 印列 → 経路列。印列・経路列は作業表のスキーマに含めない（再帰項からは未知列） |
| 型 | 印: `TO`／`DEFAULT` の共通型（省略時は boolean の `true`／`false`）。経路: `record[]`（OID 2287）。テキスト表現は `engine::sql::record_text` |

`TO`／`DEFAULT` の共通型は `select_common_type` と同じ決め方: 文字列どうしは text、整数どうし（または整数と文字列）は integer
（`i32` に収まらなければ bigint）、真偽値と文字列は boolean。解釈できない文字列は `22P02`、真偽値と整数は `42804`。

### エラー

| 条件 | wire_code |
| ---- | --------- |
| 句の構文不正（`USING` なし・符号付き定数・任意の識別子など） | `42601` |
| 循環列が列名リストに無い・印／経路の名前が列・相互・`SEARCH` の SET 名と衝突・自己参照を持たない定義への `CYCLE` | `42601` |
| 循環列の重複 | `42701` |
| `TO`／`DEFAULT` の型の不一致・解釈できない値 | `42804`／`22P02` |
| アンカー項が集合演算・`UNION`（重複除去）との併用 | `0A000` |
| 循環列の数が列数の上限を超える・反復回数／累積行数／バイト予算の超過 | `54000`（部分結果なし） |

判定順は構文（`42601`）→ 再帰構造（`42P19`）→「自己参照が無い」の `42601` → 計画（名前・型）→ 機能ゲート。

### PostgreSQL との差分（fail-closed 側に倒したもの）

- 比較できない型（`VECTOR`・`JSON`・`ARRAY`・型なし）の循環列は、PostgreSQL が実行時（`42883`）まで遅延するところを計画時に固定 `0A000` で拒否する
- `TO`／`DEFAULT` の小数・`NULL`・型名付きリテラルは固定 `0A000`（黙って別の型へ変換しない）
- 引用付きの `"true"`／`"false"` は字句段が WHERE の外では引用なしと同じ `Ident` に戻すため、真偽値リテラルとして受理される（PostgreSQL は `42601`）。`"null"` は NULL 定数として `0A000`
- 循環列に NULL を含む定義は PostgreSQL と同じく循環を検出しない。停止しない形は上限超過の `54000` で拒否する
- `UNION`（重複除去）との併用は固定 `0A000`（重複判定のキーへ印・経路を含める必要があり、`SEARCH` と `UNION` の併用と同じ扱い）
- 印列・経路列を主クエリの `WHERE`・式・集計で使う形、経路列のバイナリ結果形式は `SEARCH` の順序列と同じく未対応

### 上限と RLS-10 (b)

経路は深さに比例して増える（O(深さ) の複製）ため **複製の前に** 共有バイト予算へ計上し、印のセルも同様。超過は文全体を `54000`。循環行も
出力行なので行数上限に数える。経路の長さは反復回数 + 1 以下で、判定コストは O(深さ × 列数)。印・経路は参照セッションの可視行のセルだけから作るため、
停止時点・印・`54000` の有無は他テナントの行に左右されない（結合テスト `sql35_recursive_cte_cycle.rs` の RLS ケース）。
